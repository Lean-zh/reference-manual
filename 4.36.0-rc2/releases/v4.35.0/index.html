Lean 4.35.0 (2026-10-12)🔗

此版本合入了 214 项更改。 除下面列出的 78 项新增功能 和 57 项修复外， 还有 18 项重构， 7 项文档改进， 23 项性能改进， 2 项测试套件改进， 以及 29 项其他更改。

亮点🔗

Lean 4.35.0 最主要的新功能是 vcgen：它是 mvcgen 更快、更通用的后继。 此外新增 lake check 和 lake comparator，使用 Lean 内核检查项目；若用户要求，还可用现随工具链分发的多个独立内核检查。 策略方面重新设计了 rwa，constructor 在必须选择构造器时发出警告，grind 则通过将 BitVec 与固定位宽整数转换为 Nat、Int 算术，证明更多目标。 Decidable 改用基于 Bool 的新定义，使更多等式可由 rfl 证明。

本亮点一节由 Juanjo Madrigal 贡献。

mvcgen 的后继 vcgen🔗

Lean 4.35 提供验证条件生成器 vcgen，大多数情况下可直接替代 mvcgen；后者现已弃用。改进包括：

  1. 深度嵌入。 vcgen 基于 Std.WP 框架，其最弱前置条件解释适用于任意程序类型，而不局限于单子：除任意单子中的 do 程序外，也可验证能够定义最弱前置条件的深度嵌入语言，例如 x64 汇编 或 WebAssembly。这种通用性正是更名的原因。

  2. 更通用的断言语言。 程序逻辑的断言可位于任意完备格，因此 vcgen 不仅支持状态谓词，也支持概率逻辑、分离逻辑等断言语言；推广的框架保持概念则能让断言中未改变的部分跨调用保留。

  3. 性能。 vcgen 基于新的 SymM 框架，只将共享目标上下文内部化到 grind 的 E-图一次，因此 vcgen … with finish 可在全部验证条件间复用它。在 AddSubCancel 基准中，有状态循环体重复 2200 次，vcgen 耗时 0.32 秒，而 mvcgen 为 66 秒；内核检查所得证明分别耗时 0.53 秒和 246 秒。vcgen 运行时间随程序大小线性增长，每次循环迭代约 0.14 毫秒。

vcgen 仍标记为实验性功能：set_option experimental.vcgen true 表示接受此状态并关闭对应警告。参考手册章节和使用 vcgen 验证命令式程序教程介绍此策略。

使用 lake check 和 lake comparator 检查项目🔗

此前，用外部内核检查已完成的开发，或用 comparator 检查证明是否符合给定陈述，需要安装配置多个独立工具。 本版本将这些功能全部纳入 Lake。

#14990 新增 lake check：构建当前项目默认目标、导出结果，再通过内核重放；若任何内容使用标准公理以外的公理，则失败。 #14885 与 #15146 添加 comparator 的前端 lake comparator：给定包含定理陈述的挑战模块和解答模块，检查解答中的各指定定理是否证明挑战中的相同陈述、是否仅用允许的公理，以及是否被内核接受。 默认从 comparator.json 读取配置（#15147）：

{
  "challenge_module": "Challenge",
  "solution_module": "Solution",
  "theorem_names": ["imo2024_p1"],
  "permitted_axioms": ["propext", "Quot.sound", "Classical.choice"]
}

两个命令都将项目视为不可信输入。 构建与导出在 bubblewrap 沙箱中完成：隐藏用户主目录，仅在解析依赖时允许网络访问（#15005）；内核则在独立进程中运行（#15055）。 沙箱目前仅适用于 Linux。

发行工具链现在还包含外部检查器 lean4lean（#15048）、nanoda（#15099）、con-leche（#15130）、con-ron（#15153），以及使用加固内存分配器构建的 leanchecker 版本 leanchecker-paranoid（#14884）。 添加 --paranoid 后，两个命令除运行 Lean 自身内核外，还会运行上述全部检查器；只有每个检查器都接受时才接受项目（#15145）：

lake check              # Lean's kernel, standard axioms only
lake check --paranoid   # ...and every bundled external checker

在其他地方（例如虚拟机或计算资源更丰富的第三方）产生的导出文件，可直接用 lake check --from-export、lake comparator --solution-from-export 或 lake comparator --challenge-from-export 检查（#15157）；leanchecker 本身也新增 --from-export 标志（#15050）。

相关地，#14953 移除了自二月起已弃用的 Lean.reduceBool、Lean.reduceNat 与 Lean.trustCompiler 公理。 由于 Lean.reduceBool 和 Lean.reduceNat 的定义引用 Lean.trustCompiler，导入它们的每个环境看起来都使用此公理，使 lake check 之类的全环境公理检查意义减弱。 v4.34.0 的运行时引用计数工作也在继续，三项修复已同时回移到 v4.34.1。 #15241 和 #15289 封堵了极大输入导致官方内核释放后使用的另外两条路径；#15288 修复线程共享对象的相关问题，官方内核默认配置不会这样共享，但其他基于 Lean 的检查器可能会。 不基于 Lean 运行时的内核不受影响。

策略变更🔗

重新设计的 rwa🔗

rwa 此前只是 rw ...; assumption 的简单宏，因此 assumption 步骤可能关闭无关目标。 #14937 将其改为仅操作调用时的目标和重写产生的旁目标：rwa [rules] 重写目标并用假设关闭它；rwa [rules] at h 则重写 h，再用 h 本身而非任意匹配假设关闭主目标。 若单靠重写就已关闭目标，它会建议改用 rw：

constructor 在需要选择时发出警告🔗

多个构造器匹配目标时，constructor 此前静默选用第一个。 对于析取，这意味着总选左侧，而这往往不是用户意图。 #14854 使这种情况产生警告：

新的 constructor! 保持此前行为，但不警告。

为 lia 与 grobner 提供额外事实🔗

#15116 允许 lia、grobner 像 grind 一样接收事实和引理列表，不必先用 have 加入上下文：

def double (n : Nat) : Nat := 2 * n theorem double_def (n : Nat) : double n = 2 * n := rfl example (n : Nat) (h : double n ≤ 10) : n ≤ 5 := n:Nath:double n ≤ 10⊢ n ≤ 5 All goals completed! 🐙

grind 中的同态🔗

#14727 在 v4.34.0 准备的 [grind hom]、[grind hom_pred] 属性基础上，完成 grind 的同态支持。 带这些属性的定理描述如何将一种类型的项转换到 grind 已有求解器的其他类型。 Lean 自带 Fin、BitVec 和固定位宽整数 UInt8–UInt64、USize、Int8–Int64、ISize 等类型的转换，将它们映射到 Nat 和 Int 算术。 因此，混合机器算术和自然数界的以下目标现在可由 grind 证明：

example (x : UInt8) (h : x.toNat < 100) : (x + 1).toNat = x.toNat + 1 := x:UInt8h:x.toNat < 100⊢ (x + 1).toNat = x.toNat + 1 All goals completed! 🐙 example (x : BitVec 8) (h : x.toNat < 10) : (x * 2).toNat < 20 := x:BitVec 8h:x.toNat < 10⊢ (x * 2).toNat < 20 All goals completed! 🐙

此转换默认启用，可用 grind -hom 关闭。 它取代此前基于 Lean.Grind.ToInt 类型类的机制。

#8309 修改 Decidable 的定义：不再是带 isTrue、isFalse 构造器的归纳类型，而是保存 Bool 及其反映该命题的证明的结构体。

variable (a b : Bool) example : decide (a = true) = a := rfl example : decide (a = true ∧ b = true) = (a && b) := rfl example : decide (a = true ∨ b = true) = (a || b) := rfl example : decide (¬a) = !a := rfl

decide 也不再需要携带证明，对良好编写的实例更快。 现在推荐用 decidable_of_bool 或 decidable_of_iff 编写此类实例。 Decidable.isTrue 与 Decidable.isFalse 仍存在，也可继续用作 match 模式，因此大多数现有代码保持可用。

Lake🔗

除上述 lake check、lake comparator 外，本版本 Lake 新功能主要是面向特定情形的选项：

首次失败时停止构建

lake build --fail-fast：首次失败后停止调度新作业，允许运行中作业完成，并将跳过的作业标为 ⊘ Canceled（#14797、#14835）。

通过副本而非原地依赖本地包

在带 path 的 [[require]] 条目中设置 copy = true，或在 lakefile.lean 使用 require pkg from copy "path"；Lake 像克隆 Git 依赖一样，将包复制到工作区包目录并使用该副本（#15142）。

只预编译部分代码，而不使用 precompileModules

precompileImports 编译模块导入而非模块本身；precompileLibrary 为导入该库的模块编译整个库（#15015）。

将依赖包的构建输出上传缓存

先运行 lake build -o <file> --package <name>，再运行 lake cache put <file> --package=<name>（#15141）。

收集检查器与自定义检查的代码质量数据

lake lint --code-quality 现在也报告检查器在精译期间记录的度量（#14748、#14933），并运行以 @[package_code_quality_check] 注册的检查，包括由 --checks 传入的模块中的检查（#14716）。

另一项变更无需用户操作：依赖现在以单个修订版本的部分 Git 克隆获取，减少下载量（#14782）。 因此，在依赖内运行 git blame 等 Git 命令时，可能需要按需获取数据。

库亮点🔗

#13490 新增 Nat.powMod，无需先计算 b ^ e 就能计算 b ^ e % m。 Lean 使用 GMP 构建时，编译代码使用 GMP 模幂运算；定义本身使用平方乘法，因此内核也能高效求值。 Fin n 的幂运算现已使用它，因此即使很大的模幂也可用 decide 检查：

example : (2 : Fin 1000000007) ^ 1000000006 = 1 := a:Boolb:Bool⊢ 2 ^ 1000000006 = 1 All goals completed! 🐙

其他新增内容包括 Float、Float32 的融合乘加（#15024），更完整的 CNF 公式公开 API 与重写的 LRAT 检查器（#14842），以及 Fin、Int、Nat 和固定位宽整数缺失的序实例（#15092、#15088、#15071、#15122）。 Array、Vector 的 map、ofFn、zipWith、modify 等操作现在可跨模块边界在内核中归约，因此 decide 和 rfl 能在使用模块系统的文件中对其求值（#14270、#14989、#14996、#15078、#15079）。 向量现在使用 #v[...] 记法显示（#14545）：

#v[10, 20, 30]#eval #v[1, 2, 3].map (· * 10) 
#v[10, 20, 30]

为查找意外复制造成的性能问题，#15052 给 String、ByteArray、FloatArray、Array 添加 markLinear；#15069、#15049 为向量和哈希映射添加它。 调用 markLinear 后，对该值的每次写入都必须在它未被共享时发生；设置环境变量 LEAN_ABORT_ON_NONLINEAR 后，首次不满足要求的写入会终止程序。

破坏性变更🔗

  • #14624 修复问题 #9077：实例合成原本可能穿透类型同义词。 实例搜索期间，实例隐式参数的元变量现在只会被赋予在实例透明度意义下类型符合预期的值。 相关变更 #14583 使合一在因停滞异常放弃前，尝试剩余启发式方法。 迁移： set_option backward.isDefEq.respectTransparency.instanceSearchTypes false 恢复旧实例搜索行为，set_option backward.isDefEq.throwOnStuckAfterApp true 恢复旧合一行为。 Mathlib 中受影响的声明使用第一个选项，并附有正确修复方式的建议。

  • #8309 修改 Decidable 定义，如前所述。 由于 isTrue 与 isFalse 仍可用作模式，受影响代码较少，但依赖旧归纳定义的代码可能需要调整。

  • #14937 修改 rwa 行为，如前所述。 特别地，若重写后的 h 无法关闭目标，rwa [rules] at h 现在会失败，即使其他假设能够关闭目标。 迁移：使用 rw [rules] at h; assumption 保持旧行为；以 rw [rules] at h₁ h₂ <;> assumption 代替弃用的多位置形式。

  • #14854 多个构造器匹配时，让 constructor 发出警告。 迁移：确实要用首个构造器时使用 constructor!，否则用 left、right 等更具体的策略。

  • #14727 移除此前供 grind 算术求解器使用的 Lean.Grind.ToInt 类型类层次及其实例（仅留下也将移除的空占位类），从默认 grind 集中移除现在由同态处理的许多 BitVec、UIntN E-匹配引理，并移除 Fin.ext 的 [grind ext]。

  • #14953 移除 Lean.reduceBool、Lean.reduceNat、Lean.ofReduceBool、Lean.ofReduceNat、Lean.trustCompiler。 迁移：使用 native_decide，或在元程序中使用 Lean.Meta.nativeEqTrue。
