Lean 4.34.0 (2026-09-14)🔗

此版本合入了 159 项更改。 除下面列出的 55 项新增功能 和 63 项修复外， 有 5 处重构更改， 5 项文档改进， 6 项性能改进， 还有 2 项测试套件改进， 以及 23 项其他更改。

亮点🔗

Lean 4.34.0 重点改进内核：分析并修复了由 AI 对抗测试发现的三个可靠性问题，还加入一系列防御性检查以进一步加固。在自动化方面，bv_decide 与 sym、grind 的交互模式集成，并迁移到 SymM 预处理器，最高提速六倍。继 4.33.0 引入 Float 和 Float32 模型后，浮点 API 继续完善；检查器现在可以在命令之间保存状态，并在警告上附带代码操作，Lake 的代码检查、缓存与错误报告也得到改进。

vcgen 也取得显著进展，其重大版本计划在 v4.35.0 发布。

本亮点一节由 Juanjo Madrigal 贡献。

内核可靠性与加固🔗

延续 v4.33.0 的内核工作，本版本封堵了三条构造 False 证明的路径——两条在内核本身，一条在运行时引用计数中——并添加了一轮防御性检查。 三者均由 Daniel Selsam（OpenAI）使用内部模型报告，且都需要精心构造的输入，而非普通源代码：它们影响检查不可信来源的证明，并不影响只精译自身代码的开发。

  • #14806 使 is_def_eq 缓存不再依赖查询顺序。 内核以并查集缓存成功查询；由于实现的检查可靠但不完备，因而不满足传递性，并查集计算的传递闭包使查询答案依赖此前查询的顺序。 精心构造的输入利用这一点建立类型与计算规则不一致的递归器，从而推导 False。 现在改用以查询对为键的普通缓存，使答案重新仅依赖两个实参。 随后一个 OpenAI 智能体利用此问题构造了两种不同攻击；nanoda 和新的 lean-inductive-models 都能检测二者。

  • #14807 要求内核的 is_prop 检查结果是一个 sort。 若项的推断类型卡住而非归约到 sort，旧 is_prop 返回 false 而不拒绝该项，导致投影的证明无关性防护被跳过，允许从被当作 Prop 的值投影出数据字段。 nanoda 也接受了该伪造证明；据信 lean4lean 不存在此问题。 #14843 将相同修复应用于 inductive.h 中内联的旧检查。

  • #14838 沿用 Koka 的粘滞计数器方式，冻结 32 位引用计数溢出的对象。 强迫计数回绕会破坏对象状态；在至少有 18GB 可用内存的机器上，可将其转化为官方内核中的释放后使用，并进一步构造 False 的证明。 不依赖 Lean 运行时的内核不受影响。

本节余下内容属于加固，而非错误修复：

  • #14808 对内核为归纳类型生成的递归器进行类型检查，并检查每条计算规则保持类型，而不仅仅是类型正确。 若次要前提要求归纳假设而规则未提供，归约结果就是应用不足的函数；它仍有类型，但不再具有递归器的结果类型，因此仅检查右侧具有某个类型并不能发现问题。 这是纵深防御，仅拒绝本来就不合法的声明。

  • #14582 使内核拒绝这样一种归纳声明：正在声明的数据类型被应用于声明参数与宇宙层级以外的实参。 前端已强制此要求，因此仅影响直接通过 addDecl 构建的声明。

  • #14849 将内核计算的 Nat 数值大小限制为 128 MB，使短小证明不能再指示内核计算数 GB 的数值。 确实需要更大数值的工作负载可通过环境变量 LEAN_NAT_MAX_SIZE 提高限制。

  • #14833 要求 Lean 使用 GMP 6.3.0 或更新版本，因为旧 GMP 的缺陷可能使 Lean 在边界情况下产生不可靠结果。 使用旧 GMP 构建现在会在配置阶段失败；两个替代途径是 -DUSE_GMP=OFF（使用 Lean 自身的大整数实现）与 -DFORCE_GMP=ON。

bv_decide 提速并与 grind 协作🔗

在 grind => 中进行位展开🔗

#14672 使 bv_decide 可以在 sym => 模式中使用；#14713 将其接入 grind 状态：相关等价类及理论求解器、E-匹配学得的事实都会与目标一起编码进 SAT 问题。

opaque g : UInt8 → UInt8

example (a b d : UInt8) (h0 : d = a ||| b)
    (h1 : g d &&& 0xC0 = 0) :
    g (a ||| b) &&& 0x40 = 0 := by
  grind =>
    bv_decide

单独使用时，bv_decide 将 g d 和 g (a ||| b) 抽象为两个无关的不透明变量，报告虚假反例。 在 grind => 内，同余闭包已使用 h0 将二者合并，因此交给 SAT 求解器的正是实际需要解决的问题。

选择需要分析的类型🔗

默认情况下，bv_decide 猜测上下文中哪些结构体与枚举归纳类型可能相关，并尝试纳入它们。 #14681 新增 types [...] 子句，可显式指定类型并关闭自动发现；当目标提及许多类型、只有少数相关时，预处理仍能保持可控：

inductive Color where | red | green | blue @[ext] structure Pair where x : BitVec 8 y : BitVec 8 example (a b : Pair) (c d : Color) (h1 : a = b) (h2 : c = d) : a.x = b.x ∧ d = c := a:Pairb:Pairc:Colord:Colorh1:a = bh2:c = d⊢ a.x = b.x ∧ d = c All goals completed! 🐙

显式指定是限制而非提示：未列出的内容均视为不透明变量，因此指定错误类型会使目标超出支持范围。 既不是非递归结构体、也不是枚举归纳类型的类型会被直接拒绝。 bv_normalize、bv_decide?、bv_check 及 sym => 内也接受该子句。

注意上面的 @[ext]：bv_decide 通过结构体的外延性引理拆解结构体等式，因此没有此类引理的结构体无论是否被列出都保持不透明。

更快的预处理器🔗

#14215 将 bv_decide 的预处理器迁移到 SymM，即与 grind、cbv 共用的重写引擎。 在大型且重写密集的问题上可最高提速 6 倍，嵌入约束的替换对假设总大小变为线性复杂度。 破坏性变更： @[bv_normalize] 现在是 Sym.simp 集，其模式匹配能力和对定理形状的要求不同；bv_normalize 的证明能力也随之有所增强、有所减弱。

其他小改进包括：#14683 让嵌入约束处理同时识别 a = true 和 (!a) = true；#14460 将闭项求值扩展到更多 BitVec 运算。 在同一引擎的其他部分，#14425 允许 grind 解决有条件 Sym.simp 定理的旁条件，#14459 为 Sym.dsimp 增加重写实例内部的选项，可使更多闭项在语法上相等。

SymM 还包含一批正确性修复：匹配非线性模式时不再不可靠地合一元变量（#14404）；grind 不再丢失自定义属性中的 E-匹配定理（#14426），也不再因规范化器在跳过的绑定内部重新合成实例而漏掉有效矛盾（#14439）；整数表达式结构与其多项式表示不同时，lia/grind 不再生成被内核拒绝的证明（#13587）。 其他修复：#14401、#14405、#14424、#14428、#14444、#14664、#14691、#14694、#14709。

代码检查器与弃用警告🔗

两项变更扩展了检查器的能力。 #14357 引入有状态检查器：状态在命令精译之间保留，也可读取其他检查器的状态；采用早期/晚期两阶段架构，通过 initialize 块注册。 #14402 允许检查器产生代码操作，使警告可附带在编辑器中点击即可应用的修复。

v4.31.0 引入的弃用报告进一步完善。 #14478 将选项弃用迁至 @[deprecated] 属性，因此通过 set_option 使用或从元代码读取弃用选项时都会发出警告：

open Lean in @[deprecated "use `demo.newOpt` instead" (since := "2026-08-21")] register_option demo.oldOpt : Bool := { defValue := true, descr := "an old option" } open Lean in def readsOldOpt (o : Options) : Bool := `demo.oldOpt` has been deprecated: use `demo.newOpt` insteaddemo.oldOpt.get o 
`demo.oldOpt` has been deprecated: use `demo.newOpt` instead

#14564 重新解析模块头，使每条模块弃用警告都指向真正导入该模块的 import，而非全部堆积在头部开头；#14533 在自身已弃用的定义内部抑制语法弃用警告，与弃用常量已有的规则一致：

syntax "oldThing" : term macro_rules | `(oldThing) => `(42) deprecated_syntax termOldThing "use `42` instead" (since := "2026-08-21") def fresh : Nat := syntax 'termOldThing' has been deprecated: use `42` instead Note: This linter can be disabled with `set_option linter.deprecated.syntax false`oldThing 
syntax 'termOldThing' has been deprecated: use `42` instead

而即将被移除的定义可以继续使用同样即将移除的语法，不产生警告：

@[deprecated "use `fresh` instead" (since := "2026-08-21")] def stale : Nat := oldThing

Lake🔗

#14622 为 lake lint 增加 --code-quality 模式，将内置检查结果输出为机器可读的 JSON 条目，而非面向人的诊断；每项以检查器选项名标识。 文本检查器警告按模块与检查器汇总为包含计数的单个条目；环境检查器结果则按被标记声明报告。 条目被视为数据而非失败，因此即使发现违规，lake lint --code-quality 也会成功。 以下两个条目分别来自文本检查器的汇总和环境检查器（取自 Lake 自身测试套件）：

{"value":{"scalar":{"value":2}},
 "source":{"module":{"name":"Violations"}},
 "name":"linter.unusedVariables"}

{"value":{"scalar":{"value":1}},
 "source":{"declaration":{"name":"fooDummyMarker",
                          "module":"Violations"}},
 "name":"linter.dummyMarker"}

缓存方面，#14720 将构建期间的缓存失败降为 trace 级消息，使带 --wfail 或 --iofail 的构建不再仅因缓存而失败；#14651 修复工件传输失败未记录、终止整批传输或遗留损坏工件的多种情况。 #14724 添加 lake cache get --package，可以获取工作区指定包的输出，而非仅根包输出。

三处错误报告改进：lean 已打印真实诊断时省略 error: Lean exited with code 1（#14629）；lean_lib 根模块没有源码文件时报告底层文件错误，而非含糊的导入错误（#14625）；lake update <pkg> 对清单未知的包名现在报错，不再静默忽略（#14630）。 最后，#14723 使 MACOSX_DEPLOYMENT_TARGET 可通过 Lake API 配置，并纳入构建追踪。

性能与健壮性🔗

#14520 修复 instantiateMVars 在反复引用由 MVarId.assert/intro 引入假设的证明项上指数增长的问题；MVarId.note、replaceLocalDecl 和 simp at h 都会产生这种引用。 替换值的提升现在会在整个处理过程中记忆化并规范化，恢复线性行为：问题 #14329 的复现从使用超过 41GB 内存改善为约 1.2 秒完成精译，一个 Mathlib 模块减少了 260 亿条指令（下降 55%）。

#14397 使 set_option ... in 策略增量精译：在块内编辑时，复用未改动前导策略的结果，而不重新运行整个块。 为诊断时间开销，#14386 添加 store_traces_as name in cmd：运行 cmd，照常报告追踪，并以 name 将追踪树保存在内存中；同时提供 #postprocess_traces name post，用任意后处理器重新查看该树。 v4.33.0 的 postprocess_traces 在追踪产生时变换它，而此功能将生成与查看分开；命令本身要运行一分钟时，这一点很重要。

两项健壮性修复：#14204 检测模块 .olean 刷写失败，使磁盘耗尽不再静默留下截断文件；#14687 修复 String.Pos.Raw.extract 在切片界限极大时的释放后使用。 #14717 修复同一函数的模型与运行时不一致，并在位置已知有效时为 String.extract 添加快速路径。

FFI 方面，#14505 让每个模块初始化器在需要时调用 lean_initialize，修复私有导入 Lean 库导致的段错误。 同次清理也将 lean_initialize_runtime_module 调用变为隐式，因此将 Lean 用作 FFI 库时无需自行调用二者。

库亮点🔗

v4.33.0 开始的浮点工作继续推进。 #14481 将 Float.nan、Float.inf 及 Float32、模型对应项纳入上游，在已有 Nat.toFloat 之外添加 Int.toFloat 与 Int.toFloat32，并公开 Float.ofNat/Float.ofInt；#14495 用此前已编写但未接入的逻辑模型重新定义 Float 与固定位宽有符号整数之间的转换。

/-- info: 42.000000 -/ #guard_msgs in #eval (42 : Int).toFloat /-- info: true -/ #guard_msgs in #eval (1.0 / 0.0) == Float.inf

#14788 直接用 Bool.rec 定义 Bool.and、Bool.or 和 Bool.not，内核归约它比 match 快得多；不支持 Bool.rec 的编译器通过 @[csimp] 继续使用旧定义，因此生成代码不变。 打印其中一个定义即可看到新形式：

@[implicit_reducible] def Bool.and : Bool → Bool → Bool := fun x y => Bool.rec false y x#print Bool.and 
@[implicit_reducible] def Bool.and : Bool → Bool → Bool :=
fun x y => Bool.rec false y x

这也移除了 grind 此前为相同目的保留的内核友好副本：Bool.and'、Bool.or'、Bool.not' 现在是实际运算的弃用缩写。

HTTP 客户端新增重定向支持：#13901 添加 Std.Http.Protocol.H1.RedirectPlan，按 RFC 9110 验证重定向响应并自动跟随；#13900 添加 Std.Http.Body.Replayable，判断请求体能否在重定向请求中重放。 #14062 让 HTTP/1.1 客户端正确结束无响应体的响应读取；#14059 添加 closeWithError，允许响应体流以失败结束。

除此之外，本版本主要是增量引理改进和命名整理；命名变化汇总如下。

破坏性变更🔗

  • #14501 统一标识符中 if、dif 语法的拼写为 ite、dite，两个分支标记使用 left、right。 许多引理相应更名；最明显的是 if_pos、if_neg 现在为 ite_eq_left、ite_eq_right，dif_pos/dif_neg 现在为 dite_eq_left/dite_eq_right。 迁移：旧名保留为弃用别名，现有证明仍可运行，警告会提示替代名称。

  • #14462 将 Nat.div_eq 重命名为 Nat.div_eq_ite，Nat.mod_eq 重命名为 Nat.mod_eq_ite，腾出 Nat.div_eq 供类似 Nat.add_eq 的引理使用。 此处同样提供弃用别名。

  • #14215 将 @[bv_normalize] 改为 Sym.simp 集，如前所述。

  • #14391 将 Lean.Environment.replay 移至 Lean.Kernel.Environment.replay，因此重放环境产生 Lean.Kernel.Environment，不再经过不稳定的 Environment.ofKernelEnv。 重放环境的证明检查器等工具需要跟随更名。 迁移：旧名保留为弃用别名；警告说明类型变化，以及点记法必须改为 Kernel.Environment.replay x。

  • #14523 弃用一年前已不再使用的 letFun；请改用 have。

  • #14479 修改 IO.Error 中 osCode 的含义，模拟 POSIX errno，而不直接转发转换为无符号整数的 libuv 错误码，同时修复 lean_decode_io_error 的线程安全问题。

  • #14538 将 eq_false_of_ne_true 移至 Bool 命名空间，成为 Bool.eq_false_of_ne_true，保留弃用别名。

  • #14412 移除 ExceptCpsT.runK 未使用的 s : ε 参数。 此项没有别名：传入该实参的调用方必须删除它。

  • #14294 移除 String.toList 的 @[implicit_reducible]，使其为半可约；此前展开它会使定义相等性检查深入其内部实现。 依赖 String.toList 在隐式或可约透明度下展开的代码——定义相等性检查、实例、或陈述只有展开后才类型正确的 simp 引理——现在必须改用显式重写。

  • #14833 上述 #14833 和 #14849 会影响从源码构建 Lean 或在内核中计算极大数值的用户。

语言🔗
