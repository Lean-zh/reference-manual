Lean 4.36.0-rc2 (2026-10-27)🔗

Warning

这些发布说明描述的是候选版本，而非最终版本。 内容可能不完整，并且可能变化。

此版本合入了 219 项更改。 除下面列出的 65 项新增功能 和 83 项修复外， 还有 11 项重构， 1 项文档改进， 30 项性能改进， 3 项测试套件改进， 以及 26 项其他更改。

语言🔗

  • #15839 修复一处竞争条件：原实现本应在模块文档字符串之间持久保存作用域扩展状态，但未正确实现。修复方式是移除此错误功能，未来 PR 可能以正确版本替代。

  • #15572 为“[deprecated] 属性应指定开始弃用的日期或库版本”警告添加提示与代码操作。

  • #15499 使生成的方程引理（f.eq_1、f.eq_2 等）的陈述不依赖首次请求方程时的选项。此前首个使用方程的证明中的局部 set_option 可能改变陈述；由于证明并行精译，同一文件不同构建的陈述可能不同，导致某些线程数下编译成功、另一些下失败。

  • #15485 命令存在语法错误且禁用 showPartialSyntaxErrors 时，跳过无状态检查器。

  • #14316 使类型类解析缓存在命令间持久保存：若查询不含元变量、局部实例或自由变量，且结果本身封闭，就供后续命令复用，相同查询不再重新搜索。仅在记录的依赖未变化时使用条目，因此新实例、合一提示和可约性变化会精确使受影响条目失效。标准库构建中类型类解析时间减少约 14%，总指令数减少 1.2%；Mathlib 总体改善 0.2%，因为多数查询含尚未持久缓存的局部实例。

  • #15399 修复类型类解析缓存在可能观察到的声明改变后仍返回旧结果的问题，尤其是后续 attribute [reducible]，或作用域、局部可约性属性生效和失效时。目前缓存局限于单个命令，故较少显现，但这是跨命令共享缓存所需的前提，因为此类变化在命令间很常见。

  • #15319 新增 Expr.hasAnyMVar、Expr.containsMVar，对应已有的 Expr.hasAnyFVar、Expr.containsFVar。

  • #15355 使 SavedState.restore 丢弃被回滚的已跟踪环境变化之后记录的类型类解析缓存条目。验证条目的代次随环境回滚，但 Meta.Cache 保留，后续不同变化可能恢复记录的代次并误用旧条目；例如失败尝试中添加后回滚的实例，可能在添加另一实例后仍被返回。除修复边界情况外，这也是跨命令缓存的前提：条目需经受回溯而不对已回滚状态重新验证。

  • #15354 使类型类解析缓存条目记录搜索所查询的实例与合一提示状态，变化后即停止使用条目，即使环境变化不会清空缓存。例如，通过 liftCommandElabM 运行命令添加的实例现在能被同一计算的后续查询找到，在 CoreM 层激活的作用域实例和合一提示也同样如此。除修复边界情况外，这也是跨命令缓存的前提。

  • #15325 使类型类解析缓存结果依赖搜索读取的选项。此前命令内缓存复用忽略选项，因此项级 set_option（如 synthInstance.maxSize）下的结果可能在选项值不同的地方使用。搜索从未读取的选项仍不会划分缓存。除修复命令内边界情况外，这也是跨命令缓存的前提。

  • #15313 不再为每个函数重新推导并检查整个相互定义块的不动点方程，大幅加速大型相互 partial_fixpoint 块方程引理的实现化；200 个函数的块约快 13 倍。

  • #11386 添加标注 wf_preprocess 的定理，使用户可像使用 List.map 等常用列表函数一样，方便地使用 List.any 编写树等嵌套归纳类型上的函数。

  • #15286 使 deprecated_syntax 标注的策略每次调用至多警告一次，展开中使用的策略不再重复警告。例如弃用 mintro 后，mintro a b c 展开为 mintro a; mintro b c，原先打印五条警告，现在只有一条。

  • #15216 使 inferInstanceAs 复用非公开定义的现有实例。通过在私有作用域检查实例可复用性实现，因为此时新生成及已有实例中的辅助定义都不公开。

  • #15204 当 simp 实参是 simproc 或 simp 扩展时，拒绝 ← 修饰符，不再静默忽略。

  • #15237 添加 Environment.realizationEnvContains forConst c，报告 realizeConst forConst 回调能否访问 c。当实现化依赖多个常量时，据此选择 forConst：目标的实现化环境必须包含其余全部常量。

  • #14537 改进 rfl 等因定义相等性检查失败而失败的策略的错误消息。此前已能分析需显式显示项的哪些部分才能揭示不匹配，但有时采用错误配置；现修复这些问题。

  • #15242 去除构造 brecOn 应用中不影响结果的工作，加速结构递归定义的精译。

  • #15240 使 Meta.isProofQuick 对类型为 motive 变量应用于实参的 match 辅助函数、casesOn、brecOn 和递归器等应用给出确定答案。此前会进入 isProof 的慢路径，推断类型并归约到 sort。

  • #15239 精译结构递归定义时移除冗余的 abstractNestedProofs 处理，减少含大量此类定义的文件的精译时间。

  • #15238 移除 #15232 在 LCNF 声明扩展引入的逐声明开销；它在编译大量声明的模块时耗费约 1% 指令，同时保留已实现化常量的线性时间重放。

  • #15232 使常量实现化的代价（例如 simp only [f] 所需方程引理）不再依赖当前文件大小。此前包含大量实现化的文件会出现二次减速；4000 对定义/定理的文件精译从 99 秒降至 32 秒，每对耗时现在恒定。

  • #15230 加速含 match 的定义及使用 mkAuxDefinition、mkAuxTheorem 且 zetaDelta := false 创建的辅助定义的精译。在含 12800 个小模式匹配定义的文件中，累积精译时间从约 19 秒降至约 17 秒。

  • #15228 修复前端逐命令开销随命令在文件中位置线性增长，导致多命令文件二次增长的问题。

  • #15223 修复大量递归定义文件精译的二次减速：定义精译中的 share common exprs 每次递归调用都对完整输入文件哈希，数千个结构递归或良基递归定义的文件可能将大部分时间耗在此处。

  • #15091 为 def 契约添加位于 ensures 后的 throws e => R 子句，陈述生成规约定理的异常后置条件。它绑定抛出的异常，若为状态单子还绑定抛出时状态。throws (e : ε) s => R 的类型标注选择 ε 类型异常层；无标注则选择最外层。未提及异常层保持后置条件 ⊥，因此仍排除其异常；省略 ensures 则保持后置条件 ⊤。

  • #15064 替换 Verso 文档字符串解析器，正确跟踪底层具体语法的全部细节；同时改进文档字符串扩展 API，并使解析错误更便于采取行动。这为自动格式化 Verso 文档语法扫清障碍。

  • #15199 移除为自举引入的 Lean.Elab.BuiltinDo.Let、Lean.Elab.Do.InferControlInfo 中的 internal.parseQuotWithCurrentStage 选项，消除 #15090 引入的构建指令数回退。

库🔗

  • #15654 修复 String.toByteArray、String.toUTF8 中长期存在、由近期新增测试发现的内存泄漏。

  • #15581 将 String 的序重新定义为 UTF-8 编码的字典序，而非字符列表的字典序。

  • #15659 导出 Init.Data.Int.DivMod.Pow 中声明的引理。

  • #15651 新增 String.fromUTF8Lossy，尝试将 ByteArray 解析为 String，并按明确规定的方式用 Unicode 替代字符替换无效 UTF-8。

  • #15647 为 UIntX/IntX 位运算补齐 simproc。

  • #15628 使 Lean.Json.parse 拒绝重复键（转义解码后比较）的 JSON 对象，而非静默保留最后一个值。

  • #15594 重命名错误函数及其他辅助函数。

  • #15547 添加基于 RAII 的作用域锁守卫。

  • #15545 移除 uv 套接字、定时器和信号对象中 libuv 句柄的独立分配。

  • #15571 修复 LT JsonNumber 实例处理 0 的方式；此前 (0 : JsonNumber) < 5e-2 求值为 false。

  • #15523 修复 libuv 定时器与信号的崩溃：

    • 单次定时器和信号回调在释放事件循环对句柄的引用前兑现承诺（sync := true），导致崩溃。

    • libuv 将重复周期 0 视为单次定时器，因此周期 0 毫秒的重复 Timer 只触发一次，后续承诺一直等待。现在每毫秒触发一次。

    • Signal.cancel 只丢弃待兑现承诺，保留处理器监听；无承诺等待时到达的信号会兑现下次 next 的承诺。

    • 各平台上的信号等待器都用 Signal.toInt32 的数值兑现，而非操作系统的信号编号。

  • #15469 使 Std.Http 服务器按 RFC 9110 §5.6.7 的 HTTP-date 格式生成 Date 头，如 Sun, 06 Nov 1994 08:49:37 GMT，而非数字时区偏移（+0000）。Apache HttpClient 缓存、Go 的 http.ParseTime、Rust 的 httpdate 等严格解析 HTTP 日期的客户端不接受旧格式。

  • #15533 在 Lean 中重新实现 String.toList，同时移除所有曾有 String.data 的痕迹，后者弃用至今已近一年。

  • #15443 使 Std.Http 服务器在无时区数据库的系统（如不带 tzdata 的 ubuntu:24.04 Docker 镜像）上也能发送响应。此前生成 Date 头时需在 zoneinfo 文件中查找 UTC，导致每次连接均不返回响应就关闭。

  • #15517 将 Lean.Order.iSup、Lean.Order.iInf 的索引改为 {ι : Sort v}，使对命题 P 的 ⨆ h : P, f h 可精译。le_iSup、iSup_le、iInf_le、le_iInf、iSup_apply、iInf_apply 使用相同的 Sort 索引。

  • #15175 修复 Loop.configure 泄漏，并在分配巨大数组前拒绝超过 2^31-1 的 System.random 值。

  • #15329 为 ByteArray 添加高效 LE 与 Ord 实例，并由此推导全部其他序实例。

  • #15316 移除 Init.Data.Option.Basic 中重复派生的 BEq (Option a) 实例，改为公开 Init.Core 中派生的实例。

  • #15315 调整 Array.compareLex 和 Vector.compareLex 的属性，确保真正进行特化；此前比较函数仅通过闭包传递。

  • #15304 补齐 List、Array、Vector 的序实例。

  • #15299 使 grind 及 vcgen … with finish 更可靠地证明使用格运算的断言目标。例如 vcgen 教程的 nodup 证明现在可用 vcgen … with finish 关闭，像过去使用 mvgen 时一样。

  • #15414 降低某些过于积极、会过早触发跨理论推理的 grind E-匹配标注的激进程度。

  • #15387 为 Std.Internal.Order 的格理论添加引理及谓词变换器的计算规则。

  • #15192 修复 ContextAsync.race、ContextAsync.raceAll、ContextAsync.run、ContextAsync.background 的取消行为；Notify.notifyOne 不再将唤醒机会浪费在选择结果已决定的等待器上。

  • #15274 补齐 BitVec 的序实例。

  • #15174 解决 TCP、UDP 模块中的多个问题。

  • #15266 为 #15257 添加的 Float.minimum、Float.minimumNumber 操作提供逻辑模型。

  • #15257 定义对应 IEEE-754-2019 同名操作的 Float.minimum、Float.minimumNumber，并将 Min Float 重新定义为 Float.minimum。

  • #15115 公开 Char.ordinal、Char.ofOrdinal、Char.succ?、Char.succMany?，使其跨模块边界归约。Char 上的范围通过 UpwardEnumerable Char 实例由后两者构造，因此此前在使用模块系统的文件中，cbv、内核归约会卡在这些应用处。

  • #15247 添加基础的 CaDiCaL FFI 模块，以及与 Std.Sat API 交互的小型包装。

  • #15252 移除 withPtrEq 函数。

  • #15217 将类型变量 EPred 更名为 EPosts、值变量 epost 更名为 eposts，因为它们表示异常后置条件的集合而非单个谓词；提供 deprecated_arg 别名，使按名称传递 EPred 的代码仍能编译。

  • #15171 为一致性重命名多个 Std.WP 名称，并弃用旧名：WP.wpTrans 投影改为 WP.trans，单调性字段 WP.wp_trans_monotone 改为 WP.trans_monotone，引理 wpTrans_apply_eq 改为 trans_apply_eq。最弱前置条件单调性引理 WP.wp_consequence/wp_econs 改为统一的 wp_monotone 系列：双通道使用 wp_monotone，单通道使用 wp_monotone_post、wp_monotone_epost，空异常后置条件使用 wp_monotone_bot，并提供 _le 传递性变体。

  • #15201 重构 AIG 到 CNF 转换，从仅操作 AIG Nat 推广到泛型 AIG，有两项优势：

    2. 未来可跨多次运行增量使用 AIG 到 CNF API；为此已引入 State.cast，以跨运行复用缓存状态。

  • #15067 将框架机制扩展到 Std.WP 的异常通道。例如，异常退出携带状态的程序逻辑现在支持 ⦃P⦄ x ⦃Q; E⦄ → ⦃F ⋆ P⦄ x ⦃F ⋆ Q; F ⋆ E⦄ 这样的框架规则。框架闭包、框架条件及框架规则增加异常后置条件的配套操作 opE : R → EPred → EPred，默认忽略框架。

  • #14793 修复 #14776。

  • #14795 修复 UDP 和 TCP 模块接收函数的两个问题。

策略🔗

  • #15750 修复 #15420 引入并由 leanprover/cslib#1141 报告的两处 grind 回归：关于 λ-项上归纳谓词的证明在 v4.35.0 成功，却在 v4.36.0-rc1 失败。规范化器现在对所有 α 将 ∀ _ : α, True 重写为 True，不再仅限命题；grind 对新假设执行的立即 cases 也像其他情形拆分一样重置 E-匹配轮数。

  • #15678 修复启用 Sym.simp 规范化器（set_option backward.grind.normalizer false）时，grind 无法证明有序环中 c = b → a ≤ b + c + d → a ≤ b + b + d 等目标的问题。规范化将 b + b + d 改为 2 * b + d，使两不等式在 c = b 后不再同余，而原先没有模块关联两个和。

  • #15675 修复 linarith 在无 LawfulOrderLT 实例的类型上推理 < 时，grind 报内部错误“structure does not have a lawful LT instance”或“structure does not support LT”的问题。例如 [IntModule α] [LE α] [LT α] [IsLinearOrder α] [OrderedAdd α] (a b c : α) : a < b → b < c → a < c 现在以普通 grind failed 消息失败。

  • #15672 修复启用 Sym.simp 规范化器（set_option backward.grind.normalizer false）时，grind 无法使用域中数值 k 的 k⁻¹ 的问题。例如此前无法证明 [Field R] [IsCharP R 0] (h : f (a * 2⁻¹) = 1) (h2 : a = 2 * b) : f b = 1。

  • #15642 为基于 Sym.simp 的 grind 规范化器添加默认 false 的 Grind.Config.distrib。默认像旧规范化器一样，将 x * (y + 1) 等非常量多项式之积、和的幂、积的逆保留为因子已规范化的原子；grind +distrib 则展开为多项式范式。线性算术把非线性项视为原子，保持未展开可在导出 y + 1 = z 后保留 x * (y + 1) = x * z 等事实。

  • #15624 使 grind 将符号位宽 w 的 k#w 字面量转为所用的 BitVec 字面量 OfNat.ofNat 形式，使 Sym.simp 规范化器下 BitVec.sdiv_zero 等定理能像旧规范化器一样应用于 x.sdiv 0。

  • #15623 使基于 Sym.simp 的 grind 规范化器重写依赖命题绑定的定义域，例如将 ∀ h : i < a.size, q h 变为 ∀ h : i + 1 ≤ a.size, ...，与旧规范化器一致。

  • #15619 修复基于 Sym.simp 的 grind 规范化器处理模式含算术的 match 方程时的 panic，例如对匹配 Vec α (n + 1 + 1) 的函数使用 grind [h.eq_def]。

  • #15290 将 vcgen 语法移到新模块 Std.WP.Tactic，并弃用 Std.Do 证明模式策略。import Std.WP 现在提供 vcgen；mintro、mspec 等证明模式策略每次调用报告一条指向 vcgen 的弃用警告。无实际效果的选项 mvcgen.warning 也弃用。

  • #15298 为 Sym.Arith.normalize?（及 Sym.simp 的 arith）添加不需要旁条件的域重写。在 Field 中，a / b 变为 a * b⁻¹，先规范化逆号下的项，再将逆推到原子：(a * b)⁻¹ ↦ a⁻¹ * b⁻¹、(-a)⁻¹ ↦ -a⁻¹、a⁻¹⁻¹ ↦ a、0⁻¹ ↦ 0、1⁻¹ ↦ 1。原子或数值 x 的 x⁻¹ 随后成为多项式原子，因此 a / b + a / b 变为 2 * (a * b⁻¹)。

  • #15297 将 Sym.Arith.normalize?（及 Sym.simp 的 arith）扩展到非交换 Ring、Semiring。单项式保留因子顺序，因此 a * b 与 b * a 不同，(a + b)^2 规范化为 a^2 + a*b + b*a + b^2。项、关系及特征的支持与交换情形相同。

  • #15296 修复 Sym.simp 的 arith simproc，使原子间自反关系得以关闭：x ≤ x、x = x 现在规范化为 0 ≤ 0、0 = 0 并由 post 关闭，与此前 x + 0 ≤ x 一致。

  • #15295 使 Sym.Arith 关系规范化器（及 Sym.simp 的 arith）使用环特征，因此 UInt8 上 256 * u + v = v 规范化为 0 = 0，u + 2 = v 被识别为已规范。此前仅对项按特征取模。

  • #15293 将 Sym.Arith.normalize?（及 Sym.simp 的 arith）扩展到 CommRing、CommSemiring 上的 lhs = rhs、lhs ≤ rhs、lhs < rhs。先全部移到一侧再按符号拆分，使 x + y = z + 2 * x 变为 y = x + z，a ≤ b + a 变为 0 ≤ b；两侧归为同一多项式时关闭目标。

  • #15292 为 Sym.simp 添加 arith simproc，使用 Sym.Arith.normalize? 将环、半环项规范化为多项式范式。通过 register_sym_simp 选择启用，适合作为 pre simproc：先看到最大算术子树，用完整简化器简化其原子，再反射为语法一次。范式标为最终结果（done := true）并缓存。

  • #15280 使 Expr.toPolyS、Expr.toPolyS_nc 像 Expr.toPoly 一样处理零指数，半环中 x ^ 0 规范化为 1 而非指数为 0 的单项式。Sym.Arith 现在将 x ^ 0 : Nat 重写为 1。

  • #15279 新增 Sym.Arith.normalize?，通过反射式证明将 CommRing、CommSemiring 的项重写为多项式范式。它将供 Sym.simp 算术使用；本 PR 提供 SymM 层 API 与测试，尚未集成简化器。

  • #15267 修复 bv_decide 在投影与匹配归约方面的回归。

  • #15263 将序结构分类（LE、IsPreorder、LT、LawfulOrderLT、IsPartialOrder、IsLinearPreorder、OrderedRing）从 grind 序模块移到 Sym.Arith，供其他 Sym 组件复用。没有用户可见变化。

  • #15190 使 grind 环求解器使用 Sym.Arith 的环分类、运算缓存、反射和解释，删除 Grind/Arith/CommRing 下的重复实现。现在每次 SymM 运行只分类一次类型，而非每个目标一次，因此同次 grind 的各目标及 sym 块的各策略共享结果。通过程序驱动 grind 的代码会看到新布局：逐目标环状态仅保存求解数据，Result 携带 Sym.Arith 环记录，goalToMessageData、evalCheck 接收这些记录。

  • #15256 扩展派生值分析，允许编译器将任意形式的可能相关分配用作派生值的父项。

  • #15251 修改 ExplicitRC 确定派生借用的方式。此前立即为整个程序计算完整派生值树，使单个变量 s 总以所有控制流分支中所有可能派生值为子项；每次使用都会遍历这些子项，造成大量额外工作。新过程仅在树中保留当前程序作用域中的派生值。
