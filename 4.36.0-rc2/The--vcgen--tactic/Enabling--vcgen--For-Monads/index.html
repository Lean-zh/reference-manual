17.4. 为单子启用 vcgen🔗

若单子基于 Lean 标准库提供的单子变换器实现，例如 ExceptT 和 StateT，通常无需添加额外实例即可使用 vcgen。 其他单子则需要 WP、LawfulMonad 和 WPMonad 实例。

提供基本实例后，下一步是证明可靠性引理。 该引理应表明：运行单子计算并断言所需谓词时的最弱前置条件，确实足以证明该谓词。

除单子的定义外，典型的库还会提供一组原语运算符。 每个原语都应配备一个规约引理。 此外，将状态内部实现设为私有，并导出一组精心设计的断言运算符，可能也很有用。

库中原语运算的规约引理，应保留关于状态的所有未被刻意隐藏的事实。 虽然按运算如何将输入状态变成输出状态来思考更容易，但在后置条件为全称量化变量时，验证条件生成更可靠，因为自动化可将其直接实例化为下一条语句的前置条件，而无需证明蕴涵。

自动框架规约

函数 double 将自然数状态翻倍：

def double : StateM Nat Unit := do modify (2 * ·)

按时间顺序考虑，一个合理规约是输出状态值等于输入状态值的两倍。 使用表示初始状态的逻辑变量来表达：

theorem double_spec {n : Nat} : ⦃ fun s => s = n ⦄ double ⦃ fun _ s => s = 2 * n ⦄ := n:Nat⊢ ⦃ fun s => s = n ⦄ double ⦃ fun x s => s = 2 * n ⦄ n:Nat⊢ ⦃ fun s => s = n ⦄ modify fun x => 2 * x ⦃ fun x s => s = 2 * n ⦄ vcgen with All goals completed! 🐙

然而，等价的自动框架规约会在其他函数中使用 double 时产生更小的验证条件：

@[spec] theorem better_double_spec {Q : Unit → Nat → Prop} : ⦃ fun s => Q () (2 * s) ⦄ double ⦃ Q ⦄ := Q:Unit → Nat → Prop⊢ ⦃ fun s => Q () (2 * s) ⦄ double ⦃ Q ⦄ Q:Unit → Nat → Prop⊢ ⦃ fun s => Q () (2 * s) ⦄ modify fun x => 2 * x ⦃ Q ⦄ vcgen with All goals completed! 🐙

现在，前置条件只说明后置条件应当对初始状态的两倍成立。 Q 关于 double 未改变的状态（例如单子变换器栈中的第二层状态）所陈述的任何性质，在调用后都仍成立。 调用 double 时，vcgen 将 Q 实例化为剩余程序所需的后置条件，因此不会留下后置条件间的蕴涵作为验证条件。

better_double_spec 的前置条件恰好是 double 的最弱前置条件，因此调用方依赖 double 的完整行为。 自动框架规约也可以不规定所有细节。 例如，前置条件 fun s => ∀ s', s ≤ s' → Q () s' 只保证 double 不会减小状态。

日志单子

单子 LogM 在计算期间维护一份只可追加的日志：

structure LogM (β : Type u) (α : Type v) : Type (max u v) where log : Array β value : α instance : Monad (LogM β) where pure x := ⟨#[], x⟩ bind x f := let { log, value } := f x.value { log := x.log ++ log, value }

它还有一个 LawfulMonad 实例。

可以用 log 写入日志，并用 LogM.run 计算值及其相应日志。

def log (v : β) : LogM β Unit := { log := #[v], value := () } def LogM.run (x : LogM β α) : α × Array β := (x.value, x.log)

WP 实例没有从头编写，而是使用 PredTrans.pushArg。 该运算符原本用于建模状态单子，但 LogM 可以视为一个只能向状态追加内容的状态单子。 这种追加体现在实例主体中：初始状态会与操作产生的日志相拼接：

instance : WP (LogM β α) α (Array β → Prop) EStack⟨⟩ where wpTrans | { log, value } => PredTrans.pushArg (fun s => pure (value, s ++ log)) wp_trans_monotone x := fun _ _ _ _ _ hpost s => hpost x.value (s ++ x.log)

WPMonad 实例同样受益于这一状态单子的概念模型，证明十分简短：

可靠性引理有一个重要细节：最弱前置条件应用于空数组。 这是必要的，因为日志计算被建模为只可追加的状态，因此必须存在某个初始状态。 从语义上说，选择空数组才不会把并非来自程序的项放入日志；从技术上说，它还必须是与数组追加运算符可交换的值。

theorem LogM.of_run_eq_wp {α : Type u} {β : Type v} {x : α × Array β} {prog : LogM β α} (h : LogM.run prog = x) (P : α × Array β → Prop) (hwp : wp prog (fun v l => P (v, l)) () #[]) : P x := α:Type uβ:Type vx:α × Array βprog:LogM β αh:prog.run = xP:α × Array β → Prophwp:wp prog (fun v l => P (v, l)) () #[]⊢ P x α:Type uβ:Type vx:α × Array βprog:LogM β αh:prog.run = xP:α × Array β → Prophwp:wp prog (fun v l => P (v, l)) () #[]⊢ P prog.run α:Type uβ:Type vx:α × Array βprog:LogM β αh:prog.run = xP:α × Array β → Prophwp:P (prog.value, prog.log)⊢ P prog.run All goals completed! 🐙

接下来，应为库中的每个运算符提供规约引理。 这里只有一个运算符：log。 对于新的单子，这些证明往往必须突破霍尔三元组和最弱前置条件的抽象边界；它们提供的规约随后可由库的客户端抽象地使用。

theorem log_spec {x : β} {s' : Array β} : ⦃ fun s => s = s' ⦄ log x ⦃ fun _ s => s = s'.push x ⦄ := β:Type u_1x:βs':Array β⊢ ⦃ fun s => s = s' ⦄ log x ⦃ fun x_1 s => s = s'.push x ⦄ β:Type u_1x:βs':Array β⊢ (fun s => s = s') ⊑ wp (log x) (fun x_1 s => s = s'.push x) ⊥ All goals completed! 🐙

log 的更好规约是一条自动框架规约：

@[spec] theorem log_spec_better {x : β} {Q : Unit → Array β → Prop} : ⦃ fun s => Q () (s.push x) ⦄ log x ⦃ Q ⦄ := β:Type u_1x:βQ:Unit → Array β → Prop⊢ ⦃ fun s => Q () (s.push x) ⦄ log x ⦃ Q ⦄ β:Type u_1x:βQ:Unit → Array β → Prop⊢ (fun s => Q () (s.push x)) ⊑ wp (log x) Q ⊥ All goals completed! 🐙
