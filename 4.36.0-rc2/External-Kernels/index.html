27. 外部内核🔗

Lean 既是具有强大自动化能力的证明助手，也是一门可扩展、功能完备的编程语言。 然而，所有能在 Lean 中证明的定理都会由精译器转换到一个小得多的核心类型论中。 Lean 内核是用于检查该核心理论的小型、健壮的检查器。

如验证 Lean 证明一章所述，Lean 的设计允许独立实现的内核检查其核心理论。 这提供了额外一层保障。

Lean 发行版包含以下独立实现的内核：

Nanoda (nanoda_bin)

Chris Bailey 使用 Rust 实现的 Lean 内核（源码）。

lean4lean

Mario Carneiro 将官方内核移植到 Lean 的实现（源码）。 其中的重要部分已相对于 Lean 类型论的规约进行形式化验证。

con-leche

Lean FRO 使用 Lean 实现的 Lean 内核（源码）。 它包含一个经机器检查的证明：它接受的每个环境都具有集合论模型，因此它绝不会接受 False 的证明。

con-ron

Lean FRO 将 con-leche 移植到 Rust 的实现（源码）。

内核不需要能够调用任何特定的外部 API，也不需要使用任何特定的数据结构。 它们接收一个以换行符分隔的 JSON 文件，其中包含所有待检查的项和定义。

27.1. Lean 导出格式🔗

本节描述导出格式的 3.1.0 版本。 导出文件采用以换行符分隔的 JSON：每行包含一个对象，对象本身不含换行符。 导出的 .ndjson 文件以初始元数据对象开头，其中包含导出器、Lean 和导出格式的版本信息：

元数据对象之后是一系列带整数标号的基本对象（Name、Level 或 Expr）和声明（公理、定义、定理、不透明声明、商类型声明、归纳声明，后者包含构造器和递归器）；同一个归纳声明或相互归纳声明的相关元素（归纳规约、构造器和递归器）会被编组在一起。

导出格式包含一些冗余信息；完整的外部检查器可能会忽略这些信息，或仅验证它们（例如递归器的类型）。 包含这些信息是为了方便需要获取全部常量及其类型的其他工具（例如依赖分析工具）。

这些元素的构造方式如下所述。 为便于阅读，示例中加入了换行；请注意，NDJSON 格式要求这些 JSON 对象在实际输出时不包含任何换行。

27.1.1. 索引🔗

导出格式使用显式索引来引用名称、层级和表达式。 每种对象各自占用一张表，不同表可以复用相同的索引值。 同一张表内的每个索引都是唯一的。 本规约使用以下类型描述引用表项的自然数：

NameIdx

名称表中的索引，由 "in" 绑定。 索引 0 指向匿名名称，并且是预定义的。

LevelIdx

层级表中的索引，由 "il" 绑定。 索引 0 指向层级 0，并且是预定义的。

ExprIdx

表达式表中的索引，由 "ie" 绑定。 没有预定义的值。

NameIdxDef

本行定义的 NameIdx。

LevelIdxDef

本行定义的 LevelIdx。

ExprIdxDef

本行定义的 ExprIdx。

如果一个索引被重复定义，内核应拒绝该代码。 每个索引的定义都必须位于其所有使用之前；遇到未定义的索引时，内核应拒绝该代码。

其他整数字段表示整数值。 它们可以是 de Bruijn 索引（"bvar"）、数值名称分量（"i"）、字段索引（"idx"）、定义高度（"regular"）、构造器位置（"cidx"）或计数（"numParams"、"numIndices"、"numNested"、"numFields"、"numMotives"、"numMinors"、"nfields"）。 自然数字面量被编码为 JSON 字符串字面量而非 JSON 数字，以降低解析器在 2^{53} 等限制处截断数值的风险。

27.1.2. 名称🔗

名称有两种格式，分别对应 Lean.Name 的构造器。 索引 0 预定义为指向 Lean.Name.anonymous。

27.1.3. 层级🔗

宇宙层级有四种格式，分别对应 Lean.Level 的构造器。 索引 0 预定义为指向 Lean.Level.zero，不会另行表示。

27.1.4. 表达式🔗

精译后代码中可能出现的每个 Lean.Expr 构造器都有对应的 JSON 表示。 自由变量和元变量不会出现在导出文件中。 没有预定义的表达式。

默认情况下，导出前会去除元数据。 --export-mdata 标志使导出文件包含元数据；存在元数据时，"data" 是一个对象，其值是由 repr 格式化的字符串。

27.1.5. 声明🔗

核心类型论中的每种声明都有对应的 JSON 表示。 有时，多种 Lean 声明会精译为同一种底层表示；结构体和归纳类型就是一个例子。 这种情况下只使用一种表示。

27.1.5.5. 商类型🔗

官方 Lean 内核使用无字段的构造器 Lean.Declaration.quotDecl 作为输入来声明商类型相关声明。 随后，它会将组成商类型包的四个声明加入环境。 为方便使用，导出格式包含这些生成声明的数据。

27.1.5.6. 归纳声明🔗

官方 Lean 内核接收一个 Lean.Declaration.inductDecl，其中包含一组（相互）归纳声明及其构造器。 内核据此推导递归器及信息字段，例如 isRec、isReflexive 或 cidx。 为方便使用，导出格式包含这些生成声明的数据。 ι-归约由 RecursorRule 条目指定。 独立内核可以信任文件中包含的派生递归器信息，也可以重新生成并检查它们，以获得额外保障。
