16.13. 交互模式🔗

由于 grind 依赖当前的已标注引理集合，库中的标注变化后，证明可能失效或变慢。 此外，搜索证明时，grind 可能尝试许多对最终结果没有贡献的步骤，这也需要时间。 可以用脚本替代 grind 的搜索，直接沿着成功的证明路径前进，并且只实例化真正对证明有贡献的引理。 重新检查这样的证明既更快，也更能适应库的变化。 这一脚本功能称为 grind 的交互模式，脚本使用专用策略语言编写。

grind 交互模式脚本由 Lean.Parser.Tactic.grind : tactic`grind` 是受现代 SMT 求解器启发的策略。 **可以想象一块虚拟白板**：每当 grind 发现新的等式、不等式或逻辑事实，就将其写在白板上，把已知相等的项归为一组，让各个推理引擎读取共享工作区并向其中贡献信息。 这些引擎协同处理等式推理、应用已知定理、传播新事实、执行分类讨论，并运行线性算术、交换环等领域的专用求解器。 更多信息见[参考手册的 `grind` 章节](https://lean-lang.org/doc/reference/4.36.0-rc2/find/?domain=Verso.Genre.Manual.section&name=grind-tactic)。 `grind` *不适合*搜索空间会组合爆炸的目标，例如大型鸽巢原理实例、图着色归约、高阶 N 皇后棋盘，或编码为布尔约束的 200 变量数独。 这些编码需要成千上万乃至数百万次分类讨论，超出了 `grind` 分支搜索的承受能力。 对于**位级或组合问题**，可以考虑 **`bv_decide`**。 `bv_decide` 调用先进的 SAT 求解器 CaDiCaL，并返回*紧凑、可由机器检查的证书*。 ### 等式推理 `grind` 使用**同余闭包**追踪项之间的等式。 当已知两个项相等时，同余闭包会自动推导由它们组成的更复杂表达式之间的等式。 例如，若 `a = b`，则对于任意函数 `f`，同余闭包也会推得 `f a = f b`。 这是 `grind` 高效等式推理的基础。 例如： ``` example (f : Nat → Nat) (h : a = b) : f (f b) = f (f a) := by grind ``` ### 使用 E-匹配应用定理 为了应用已有定理，`grind` 使用 **E-匹配**技术，在考虑等式的同时为已知定理模式寻找匹配。 E-匹配与同余闭包相结合，使 `grind` 能自动发现定理和等式的不明显推论。 考虑以下函数和定理： ``` def f (a : Nat) : Nat := a + 1 def g (a : Nat) : Nat := a - 1 @[grind =] theorem gf (x : Nat) : g (f x) = x := by simp [f, g] ``` 定理 `gf` 断言，对所有自然数 `x` 都有 `g (f x) = x`。 属性 `[grind =]` 指示 `grind` 使用等式左端 `g (f x)` 作为 E-匹配模式。 假设现在有以下目标： ``` example {a b} (h : f b = a) : g a = b := by grind ``` 虽然 `g a` 不是模式 `g (f x)` 的实例，但模等式 `f b = a` 后它就是了。 在 `g a` 中用 `f b` 替换 `a`，得到 `g (f b)`，它在赋值 `x := b` 下匹配模式 `g (f x)`。 因此，定理 `gf` 被实例化为 `x := b`，并断言新的等式 `g (f b) = b`。 随后，`grind` 使用同余闭包推导蕴含的等式 `g a = g (f b)`，完成证明。 用于实例化定理的模式会影响 `grind` 的有效性。 例如，在以下情形中，模式 `g (f x)` 过于严格：目标中甚至不含函数符号 `g`，因此定理 `gf` 不会被实例化。 ``` example (h₁ : f b = a) (h₂ : f c = a) : b = c := by grind ``` 可以使用命令 `grind_pattern` 手动为给定定理选择模式。 下面指示 `grind` 使用 `f x` 作为模式，使它能自动解决目标： ``` grind_pattern gf => f x example {a b c} (h₁ : f b = a) (h₂ : f c = a) : b = c := by grind ``` 启用选项 `trace.grind.ematch.instance`，可让 `grind` 为生成的每个定理实例打印跟踪消息。 也可以指定**多重模式**，控制 `grind` 何时应用定理。 多重模式要求在当前上下文中匹配所有指定模式后，才能应用定理。 这对传递性规则等定理很有用，因为它们的多个前提必须同时存在，规则才能应用。 下面使用二元关系 `R` 的传递性公理演示： ``` opaque R : Int → Int → Prop axiom Rtrans {x y z : Int} : R x y → R y z → R x z grind_pattern Rtrans => R x y, R y z example {a b c d} : R a b → R b c → R c d → R a d := by grind ``` 指定多重模式 `R x y, R y z`，会指示 `grind` 仅当上下文中同时存在 `R x y` 和 `R y z` 时才实例化 `Rtrans`。 在此例中，`grind` 应用 `Rtrans`，由 `R a b` 和 `R b c` 推得 `R a c`，再重复同样的推理，由 `R a c` 和 `R c d` 推得 `R a d`。 除了使用 `grind_pattern` 显式指定模式，也可以使用 `@[grind]` 属性或其变体，借助启发式方法生成（多重）模式。 完整列表见参考手册，主要形式如下： - `@[grind →]` 从定理假设中选择多重模式，即使用定理进行正向推理。具体而言，它从左到右遍历假设，每遇到一个最小可索引（即头部为常量）、且“覆盖”（即确定其值）某个此前未覆盖参数的子表达式，就将其加入模式，直到所有参数都被覆盖。 - `@[grind ←]` 从定理结论中选择多重模式，即使用定理进行反向推理。若某些定理参数未出现在结论中，此过程可能失败。 - `@[grind]` 先遍历结论，再从左到右遍历假设；在模式扩大参数覆盖范围时将其加入，直到所有参数都被覆盖。 - `@[grind =]` 检查定理结论是等式，然后使用等式左端作为模式。若某些参数未出现在左端，此过程可能失败。 以下用属性 `[grind →]` 重写此前的例子： ``` opaque R : Int → Int → Prop @[grind →] axiom Rtrans {x y z : Int} : R x y → R y z → R x z example {a b c d} : R a b → R b c → R c d → R a d := by grind ``` 为控制定理实例化并避免产生无穷多个实例，`grind` 使用生成层级计数器。 原始目标中的项被赋予生成层级零。 当 `grind` 使用生成层级不超过 `n` 的项应用定理时，新创建的项会被赋予生成层级 `n + 1`。 这限制了应用定理时探索的深度，有助于防止过量实例化。 #### 主要选项 - `grind (ematch := <num>)` 控制 E-匹配轮数。 - `grind [<name>, ...]` 指示 `grind` 在 E-匹配中使用声明 `name`。 - `grind only [<name>, ...]` 类似于 `grind [<name>, ...]`，但不使用标注了 `@[grind]` 的定理。 - `grind (gen := <num>)` 设置最大生成层级。 ### 线性整数算术（`lia`） `grind` 通过集成的 **`lia`** 决定过程，能够解决可归约到**线性整数算术（LIA）**的目标。 它支持： * 等式 `p = 0`； * 不等式 `p ≤ 0`； * 不等关系 `p ≠ 0`； * 整除关系 `d ∣ p`。 求解器增量地为变量赋整数值；若部分赋值违反某个约束，就添加一个新推导出的约束并重试。 这种*基于模型*的搜索对于 **LIA 是完备的**。 #### 主要选项 * `grind -lia` 禁用求解器，可用于调试。 * `grind +qlia` 接受有理数模型，缩小搜索空间，但对 ℤ 不再完备。 * `grind (liaSteps := n)` 限制模型搜索执行的步数；达到阈值后，求解器不再完备。 #### 示例 ``` -- Even + even is never odd. example {x y : Int} : 2 * x + 4 * y ≠ 5 := by grind -- Mixing equalities and inequalities. example {x y : Int} : 2 * x + 3 * y = 0 → 1 ≤ x → y < 1 := by grind -- Reasoning with divisibility. example (a b : Int) : 2 ∣ a + 1 → 2 ∣ b + a → ¬ 2 ∣ b + 2 * a := by grind example (x y : Int) : 27 ≤ 11*x + 13*y → 11*x + 13*y ≤ 45 → -10 ≤ 7*x - 9*y → 7*x - 9*y ≤ 4 → False := by grind -- Types that implement the `ToInt` type-class. example (a b c : UInt64) : a ≤ 2 → b ≤ 3 → c - a - b = 0 → c ≤ 5 := by grind ``` ### 代数求解器（`ring`） `grind` 内置了称为 **`ring`** 的代数求解器，处理能够表述为交换环、半环或域上多项式等式或不等关系的目标。 *开箱即用*：所有核心数值类型及相关 Mathlib 类型都已提供所需的类型类实例，因此求解器可直接用于大多数开发工作。 它能够判定或处理： * 形如 `p = q` 的等式； * 不等关系 `p ≠ q`； * 涉及域中逆元的基本推理（`a / b := a * b⁻¹`）； * 将环的事实与其他 `grind` 引擎混合使用的目标。 #### 主要选项 * `grind -ring` 关闭求解器，可用于调试。 * `grind (ringSteps := n)` 限制此过程执行的步数。 #### 示例 ``` open Lean Grind example [CommRing α] (x : α) : (x + 1) * (x - 1) = x^2 - 1 := by grind -- Characteristic 256 means 16 * 16 = 0. example [CommRing α] [IsCharP α 256] (x : α) : (x + 16) * (x - 16) = x^2 := by grind -- Works on built-in rings such as `UInt8`. example (x : UInt8) : (x + 16) * (x - 16) = x^2 := by grind example [CommRing α] (a b c : α) : a + b + c = 3 → a^2 + b^2 + c^2 = 5 → a^3 + b^3 + c^3 = 7 → a^4 + b^4 = 9 - c^4 := by grind example [Field α] [NoNatZeroDivisors α] (a : α) : 1 / a + 1 / (2 * a) = 3 / (2 * a) := by grind ``` ### 其他选项 - `grind (splits := <num>)` 限制搜索树的*深度*。一条分支执行了 `num` 次拆分后，`grind` 不再继续拆分该分支。 - `grind -splitIte` 禁用对 if-then-else 表达式的分类讨论。 - `grind -splitMatch` 禁用对 `match` 表达式的分类讨论。 - `grind +splitImp` 指示 `grind` 对前件 `A` 为**命题**的任何假设 `A → B` 进行拆分。 - `grind -linarith` 禁用用于（有序）模和环的线性算术求解器。 ### 更多示例 ``` example {a b} {as bs : List α} : (as ++ bs ++ [b]).getLastD a = b := by grind example (x : BitVec (w+1)) : (BitVec.cons x.msb (x.setWidth w)) = x := by grind example (as : Array α) (lo hi i j : Nat) : lo ≤ i → i < j → j ≤ hi → j < as.size → min lo (as.size - 1) ≤ i := by grind ```grind => 及其后缩进的 grind 策略块组成。 每个策略会运行 grind 的某个引擎、实例化定理、拆分情形、检查共享状态或管理剩余目标。 这些步骤操作自动搜索所使用的同一块“白板”：此前各步骤发现的等式、不等式、布尔事实及由它们导出的等价类。

交互模式也能帮助理解 grind 为何无法完成证明。 检查策略揭示白板的当前状态，可能让用户发现缺失的定理实例化或情形拆分；这些可以通过若干显式步骤或库中的额外标注补足。 显式脚本也可以帮助读者理解 grind 成功的原因。

结构体 Two 可视为用 Bool 而非 Nat 索引的双元素数组。

structure Two α where fst : α snd : α namespace Two def get (xs : Two α) (i : Bool) : α := if i then xs.fst else xs.snd

### 线性整数算术（`lia`）

`grind` 通过集成的 **`lia`** 决定过程，能够解决可归约到**线性整数算术（LIA）**的目标。
它支持：

* 等式 `p = 0`；
* 不等式 `p ≤ 0`；
* 不等关系 `p ≠ 0`；
* 整除关系 `d ∣ p`。

求解器增量地为变量赋整数值；若部分赋值违反某个约束，就添加一个新推导出的约束并重试。
这种*基于模型*的搜索对于 **LIA 是完备的**。

#### 主要选项

* `grind -lia` 禁用求解器，可用于调试。
* `grind +qlia` 接受有理数模型，缩小搜索空间，但对 ℤ 不再完备。
* `grind (liaSteps := n)` 限制模型搜索执行的步数；达到阈值后，求解器不再完备。

#### 示例

```
-- Even + even is never odd.
example {x y : Int} : 2 * x + 4 * y ≠ 5 := by
  grind

-- Mixing equalities and inequalities.
example {x y : Int} :
    2 * x + 3 * y = 0 → 1 ≤ x → y < 1 := by
  grind

-- Reasoning with divisibility.
example (a b : Int) :
    2 ∣ a + 1 → 2 ∣ b + a → ¬ 2 ∣ b + 2 * a := by
  grind

example (x y : Int) :
    27 ≤ 11*x + 13*y →
    11*x + 13*y ≤ 45 →
    -10 ≤ 7*x - 9*y →
    7*x - 9*y ≤ 4 → False := by
  grind

-- Types that implement the `ToInt` type-class.
example (a b c : UInt64)
    : a ≤ 2 → b ≤ 3 → c - a - b = 0 → c ≤ 5 := by
  grind
```

### 代数求解器（`ring`）

`grind` 内置了称为 **`ring`** 的代数求解器，处理能够表述为交换环、半环或域上多项式等式或不等关系的目标。

*开箱即用*：所有核心数值类型及相关 Mathlib 类型都已提供所需的类型类实例，因此求解器可直接用于大多数开发工作。

它能够判定或处理：

* 形如 `p = q` 的等式；
* 不等关系 `p ≠ q`；
* 涉及域中逆元的基本推理（`a / b := a * b⁻¹`）；
* 将环的事实与其他 `grind` 引擎混合使用的目标。

#### 主要选项

* `grind -ring` 关闭求解器，可用于调试。
* `grind (ringSteps := n)` 限制此过程执行的步数。

#### 示例

```

16.13.2.1. 锚点🔗

若干策略通过锚点引用白板条目，写作 # 后接十六进制数，例如 #1a。 锚点代替名称，用于标识特定事实、等价类或情形拆分候选项。 锚点会出现在检查策略的输出或筛选后的状态中。 cases? 和 show_cases 会报告 cases 可操作的锚点。

锚点是所引用项的稳定哈希。 它根据项的结构计算，并刻意忽略内部名称和实例实参等不稳定的实现细节。 因此，许多无关的证明变化不会影响锚点；但被引用项的结构改变时，锚点仍可能变化。 所以，只要引用候选项的结构保持不变，就可以将 cases? 产生的锚点保存在脚本文件中。

某些情况下，多个项可能具有同一锚点。 用锚点实例化时，会实例化共享该锚点的所有项；情形拆分则需要更精确的控制。 若多个情形拆分候选项共享锚点，则会为其分配序号消歧标记：用连续数字记录它们加入白板的顺序。 这些数字写在 / 后，例如 #7a83/2 表示锚点为 #7a83 的第二个项。 具有给定锚点的首个项编号为 1，因此 #7a83/1 等价于 #7a83。 由于按顺序分配，序号不如锚点稳定；调整假设顺序就可能改变序号。

1 @[grind =] theorem gf (x : Nat) : g (f x) = x := by simp [f, g] ``` 定理 `gf` 断言，对所有自然数 `x` 都有 `g (f x) = x`。 属性 `[grind =]` 指示 `grind` 使用等式左端 `g (f x)` 作为 E-匹配模式。 假设现在有以下目标： ``` example {a b} (h : f b = a) : g a = b := by grind ``` 虽然 `g a` 不是模式 `g (f x)` 的实例，但模等式 `f b = a` 后它就是了。 在 `g a` 中用 `f b` 替换 `a`，得到 `g (f b)`，它在赋值 `x := b` 下匹配模式 `g (f x)`。 因此，定理 `gf` 被实例化为 `x := b`，并断言新的等式 `g (f b) = b`。 随后，`grind` 使用同余闭包推导蕴含的等式 `g a = g (f b)`，完成证明。 用于实例化定理的模式会影响 `grind` 的有效性。 例如，在以下情形中，模式 `g (f x)` 过于严格：目标中甚至不含函数符号 `g`，因此定理 `gf` 不会被实例化。 ``` example (h₁ : f b = a) (h₂ : f c = a) : b = c := by grind ``` 可以使用命令 `grind_pattern` 手动为给定定理选择模式。 下面指示 `grind` 使用 `f x` 作为模式，使它能自动解决目标： ``` grind_pattern gf => f x example {a b c} (h₁ : f b = a) (h₂ : f c = a) : b = c := by grind ``` 启用选项 `trace.grind.ematch.instance`，可让 `grind` 为生成的每个定理实例打印跟踪消息。 也可以指定**多重模式**，控制 `grind` 何时应用定理。 多重模式要求在当前上下文中匹配所有指定模式后，才能应用定理。 这对传递性规则等定理很有用，因为它们的多个前提必须同时存在，规则才能应用。 下面使用二元关系 `R` 的传递性公理演示： ``` opaque R : Int → Int → Prop axiom Rtrans {x y z : Int} : R x y → R y z → R x z grind_pattern Rtrans => R x y, R y z example {a b c d} : R a b → R b c → R c d → R a d := by grind ``` 指定多重模式 `R x y, R y z`，会指示 `grind` 仅当上下文中同时存在 `R x y` 和 `R y z` 时才实例化 `Rtrans`。 在此例中，`grind` 应用 `Rtrans`，由 `R a b` 和 `R b c` 推得 `R a c`，再重复同样的推理，由 `R a c` 和 `R c d` 推得 `R a d`。 除了使用 `grind_pattern` 显式指定模式，也可以使用 `@[grind]` 属性或其变体，借助启发式方法生成（多重）模式。 完整列表见参考手册，主要形式如下： - `@[grind →]` 从定理假设中选择多重模式，即使用定理进行正向推理。具体而言，它从左到右遍历假设，每遇到一个最小可索引（即头部为常量）、且“覆盖”（即确定其值）某个此前未覆盖参数的子表达式，就将其加入模式，直到所有参数都被覆盖。 - `@[grind ←]` 从定理结论中选择多重模式，即使用定理进行反向推理。若某些定理参数未出现在结论中，此过程可能失败。 - `@[grind]` 先遍历结论，再从左到右遍历假设；在模式扩大参数覆盖范围时将其加入，直到所有参数都被覆盖。 - sym 是 Lean.Parser.Tactic.grind : tactic`grind` 是受现代 SMT 求解器启发的策略。 **可以想象一块虚拟白板**：每当 grind 发现新的等式、不等式或逻辑事实，就将其写在白板上，把已知相等的项归为一组，让各个推理引擎读取共享工作区并向其中贡献信息。 这些引擎协同处理等式推理、应用已知定理、传播新事实、执行分类讨论，并运行线性算术、交换环等领域的专用求解器。 更多信息见[参考手册的 `grind` 章节](https://lean-lang.org/doc/reference/4.36.0-rc2/find/?domain=Verso.Genre.Manual.section&name=grind-tactic)。 `grind` *不适合*搜索空间会组合爆炸的目标，例如大型鸽巢原理实例、图着色归约、高阶 N 皇后棋盘，或编码为布尔约束的 200 变量数独。 这些编码需要成千上万乃至数百万次分类讨论，超出了 `grind` 分支搜索的承受能力。 对于**位级或组合问题**，可以考虑 **`bv_decide`**。 `bv_decide` 调用先进的 SAT 求解器 CaDiCaL，并返回*紧凑、可由机器检查的证书*。 ### 等式推理 `grind` 使用**同余闭包**追踪项之间的等式。 当已知两个项相等时，同余闭包会自动推导由它们组成的更复杂表达式之间的等式。 例如，若 `a = b`，则对于任意函数 `f`，同余闭包也会推得 `f a = f b`。 这是 `grind` 高效等式推理的基础。 例如： ``` example (f : Nat → Nat) (h : a = b) : f (f b) = f (f a) := by grind ``` ### 使用 E-匹配应用定理 为了应用已有定理，`grind` 使用 **E-匹配**技术，在考虑等式的同时为已知定理模式寻找匹配。 E-匹配与同余闭包相结合，使 `grind` 能自动发现定理和等式的不明显推论。 考虑以下函数和定理： ``` def f (a : Nat) : Nat := a + 1 def g (a : Nat) : Nat := a - 1 @[grind =] theorem gf (x : Nat) : g (f x) = x := by simp [f, g] ``` 定理 `gf` 断言，对所有自然数 `x` 都有 `g (f x) = x`。 属性 `[grind =]` 指示 `grind` 使用等式左端 `g (f x)` 作为 E-匹配模式。 假设现在有以下目标： ``` example {a b} (h : f b = a) : g a = b := by grind ``` 虽然 `g a` 不是模式 `g (f x)` 的实例，但模等式 `f b = a` 后它就是了。 在 `g a` 中用 `f b` 替换 `a`，得到 `g (f b)`，它在赋值 `x := b` 下匹配模式 `g (f x)`。 因此，定理 `gf` 被实例化为 `x := b`，并断言新的等式 `g (f b) = b`。 随后，`grind` 使用同余闭包推导蕴含的等式 `g a = g (f b)`，完成证明。 用于实例化定理的模式会影响 `grind` 的有效性。 例如，在以下情形中，模式 `g (f x)` 过于严格：目标中甚至不含函数符号 `g`，因此定理 `gf` 不会被实例化。 ``` example (h₁ : f b = a) (h₂ : f c = a) : b = c := by grind ``` 可以使用命令 `grind_pattern` 手动为给定定理选择模式。 下面指示 `grind` 使用 `f x` 作为模式，使它能自动解决目标： ``` grind_pattern gf => f x example {a b c} (h₁ : f b = a) (h₂ : f c = a) : b = c := by grind ``` 启用选项 `trace.grind.ematch.instance`，可让 `grind` 为生成的每个定理实例打印跟踪消息。 也可以指定**多重模式**，控制 `grind` 何时应用定理。 多重模式要求在当前上下文中匹配所有指定模式后，才能应用定理。 这对传递性规则等定理很有用，因为它们的多个前提必须同时存在，规则才能应用。 下面使用二元关系 `R` 的传递性公理演示： ``` opaque R : Int → Int → Prop axiom Rtrans {x y z : Int} : R x y → R y z → R x z grind_pattern Rtrans => R x y, R y z example {a b c d} : R a b → R b c → R c d → R a d := by grind ``` 指定多重模式 `R x y, R y z`，会指示 `grind` 仅当上下文中同时存在 `R x y` 和 `R y z` 时才实例化 `Rtrans`。 在此例中，`grind` 应用 `Rtrans`，由 `R a b` 和 `R b c` 推得 `R a c`，再重复同样的推理，由 `R a c` 和 `R c d` 推得 `R a d`。 除了使用 `grind_pattern` 显式指定模式，也可以使用 `@[grind]` 属性或其变体，借助启发式方法生成（多重）模式。 完整列表见参考手册，主要形式如下： - `@[grind →]` 从定理假设中选择多重模式，即使用定理进行正向推理。具体而言，它从左到右遍历假设，每遇到一个最小可索引（即头部为常量）、且“覆盖”（即确定其值）某个此前未覆盖参数的子表达式，就将其加入模式，直到所有参数都被覆盖。 - `@[grind ←]` 从定理结论中选择多重模式，即使用定理进行反向推理。若某些定理参数未出现在结论中，此过程可能失败。 - `@[grind]` 先遍历结论，再从左到右遍历假设；在模式扩大参数覆盖范围时将其加入，直到所有参数都被覆盖。 - `@[grind =]` 检查定理结论是等式，然后使用等式左端作为模式。若某些参数未出现在左端，此过程可能失败。 以下用属性 `[grind →]` 重写此前的例子： ``` opaque R : Int → Int → Prop @[grind →] axiom Rtrans {x y z : Int} : R x y → R y z → R x z example {a b c d} : R a b → R b c → R c d → R a d := by grind ``` 为控制定理实例化并避免产生无穷多个实例，`grind` 使用生成层级计数器。 原始目标中的项被赋予生成层级零。 当 `grind` 使用生成层级不超过 `n` 的项应用定理时，新创建的项会被赋予生成层级 `n + 1`。 这限制了应用定理时探索的深度，有助于防止过量实例化。 #### 主要选项 - 使用 sym 时，必须像标准证明策略语言那样手动引入假设。 引入假设会将其从目标结论移到新的假设中。 通常还需要将假设加入“白板”，让它参与同余闭包及 grind 的其他处理过程。 将假设或项加入白板称为内部化。 内部化之后，假设参与同余推理、约束传播和理论求解器；在此之前，grind 不会对其进行推理。
