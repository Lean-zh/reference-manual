17.2. 谓词变换器概述🔗

谓词变换器语义将程序解释为从谓词到谓词的函数，而不是从值到值的函数。 后置条件是在程序运行后成立的断言；前置条件则是为了保证后置条件成立而必须在程序运行前成立的断言。

vcgen 使用的谓词变换器语义将后置条件变换为程序能够保证该后置条件成立时的最弱前置条件。 若在所有状态下 P' 都足以证明 P，但 P 不足以证明 P'，则断言 P 弱于 P'。 逻辑等价的断言视为相等。

这里的谓词可以带状态：它们可以提及程序的当前状态。 此外，后置条件还可以把程序的返回值及其抛出的任何异常与最终状态关联起来。 每个可用于 vcgen 的程序类型都由 WP 实例指定断言类型和异常后置条件类型。 对于 StateM Nat 这样的状态单子，断言是状态上的谓词，类型为 Nat → Prop。 后置条件还将返回值作为首个参数，异常后置条件则为程序可能抛出的每种异常提供一个断言。

17.2.1. 断言格🔗

程序的谓词变换器语义基于一种命题可以提及程序状态的逻辑。 这里的“状态”不仅指可变状态，也包括通过 ReaderT 等方式提供的只读值。 不同程序类型具有不同的断言类型，它可以是任意完备格。 更具体地说，断言类型需实例化 Assertion；它是建立在 CompleteLattice 上、可被 vcgen 识别的 Lean.Parser.Command.classAbbrev : command将 ``` class abbrev C <params> := D_1, ..., D_n ``` 展开为 ``` class C <params> extends D_1, ..., D_n attribute [instance] C.mk ```class abbrev。

格结构提供断言的逻辑词汇：

  • 序关系 ⊑ 表示蕴涵。

  • 交 ⊓ 表示合取，并 ⊔ 表示析取。

  • 顶元 ⊤ 是平凡断言，底元 ⊥ 是矛盾断言。

  • 带索引的上确界 ⨆ 表示存在量化，带索引的下确界 ⨅ 表示全称量化。 其记法类似普通量词；例如 ⨆ x : α, P x 断言存在满足 P 的元素。

  • Heyting 蕴涵 ⇨ 是断言语言内部的蕴涵。

蕴涵关系与内部蕴涵的区别在于：前者是 Lean 逻辑中的陈述，后者属于断言语言；对断言 P 和 Q，P ⊑ Q 是 Prop，而 P ⇨ Q 仍是一个断言。

Std.WP 为 Prop、Unit、函数类型和有序对提供 Assertion 实例。 Prop 上的格运算与普通逻辑联结词一致，其序关系就是逻辑蕴涵。 Nat → Prop 等函数类型上的格运算逐点进行，因此状态谓词间的蕴涵是全称量化的蕴涵。 (Nat → Prop) × (Bool → Prop) 等有序对上的格运算逐分量进行，因此成对谓词间的蕴涵是各分量谓词间蕴涵的合取。

不同断言类型上的蕴涵

在 Prop 上，蕴涵关系就是逻辑蕴涵：

example (P Q : Prop) : (P ⊑ Q) = (P → Q) := rfl

在状态谓词类型上，蕴涵关系就是每个状态上的逻辑蕴涵：

example (f g : Nat → Prop) : (f ⊑ g) = ∀ n, f n → g n := rfl

有序对间的蕴涵关系是各分量蕴涵关系的合取：

example (f₁ f₂ : Nat → Prop) (g₁ g₂ : Bool → Prop) : ((f₁, g₁) ⊑ (f₂, g₂)) = ((f₁ ⊑ f₂) ∧ (g₁ ⊑ g₂)) := rfl

通过展开蕴涵序关系并对各个状态推理，可以证明状态谓词间的具体蕴涵：

def Positive : Nat → Prop := fun n => 0 < n def AtLeastTwo : Nat → Prop := fun n => 2 ≤ n example : AtLeastTwo ⊑ Positive := ⊢ AtLeastTwo ⊑ Positive ⊢ ∀ (x : Nat), 2 ≤ x → 0 < x x:Nath:2 ≤ x⊢ 0 < x All goals completed! 🐙

将命题嵌入完全格类型。 当 p : Prop 成立时，⌜p⌝ 将其嵌入为 ⊤；否则嵌入为 ⊥。

形如 ⌜p⌝ 的断言是纯断言：其真假不依赖状态。 在断言类型 Prop 上，⌜p⌝ 就是命题 p 本身；在 Nat → Prop 等状态谓词类型上，它是常值谓词 fun _ => p。 因此，具体单子的规约可以直接陈述命题，例如 fun s => s = n。 断言类型抽象时必须使用角括号，例如对单子及其断言类型 Pred 量化的规约。 此时 n = k 这样的命题不是断言，但 ⌜n = k⌝ 将它嵌入 Pred。 本章末尾的单子多态示例正是因此而使用角括号。 vcgen 将纯前置条件移入普通 Lean 上下文，使其成为验证条件的假设。

17.2.2. 异常后置条件🔗

正常终止的后置条件是从返回值到断言的函数。 可能抛出异常的程序还需要异常后置条件，断言程序抛出异常时成立的性质。 给定单子的异常后置条件类型由其 WP 实例决定。

例如，ExceptT String (StateM Nat) Bool 的 WP 实例指定断言类型为 Nat → Prop，从而后置条件类型为 Bool → Nat → Prop，异常后置条件类型为 String → Nat → Prop。 没有异常的单子具有异常后置条件类型 Unit。

对于断言类型为 Pred、异常后置条件类型为 EPred 的底层单子，ExceptT ε 这样的异常层会增加一个异常后置条件，得到类型 (ε → Pred) × EPred。

由于单元类型与有序对类型都具有 Assertion 实例，这些异常后置条件“栈”自动也是断言。 单子变换器的 WP 实例确保单子变换器栈具有相应的异常后置条件栈。

语法异常后置条件栈

记法 EStack⟨e₁, e₂, ...⟩ 是异常后置条件栈类型 e₁ × (e₂ × (... × Unit)) 的简写，记法 estack⟨v₁, v₂, ...⟩ 则构造该栈类型的值 (v₁, v₂, ..., ())。

term ::= ...
    | 异常后置条件栈的**类型**：`EStack⟨ε₁ → l, ε₂ → l⟩` 即 `(ε₁ → l) × (ε₂ → l) × EStack⟨⟩`。EStack⟨term,*⟩
term ::= ...
    | 异常后置条件栈的**值**：`estack⟨e₁, e₂⟩` 即 `(e₁, e₂, ())`。estack⟨term,*⟩

可能抛出异常的程序有两种规约解释。全正确性解释 ⦃P⦄ prog ⦃Q'⦄ 断言：若 P 成立，则 prog 正常终止，且结果满足 Q'。部分正确性解释 ⦃P⦄ prog ⦃Q'; ⊤⦄ 断言：若 P 成立，且 prog 正常终止，则结果满足 Q'。 不显式提供异常后置条件的三元组使用底元断言 (⊥ : EPred)，因此采用全正确性解释；在 ⊥ 与 ⊤ 之间，异常后置条件表达一系列不同的正确性性质。

谓词变换器是从后置条件到描述前置条件的断言的函数。

将谓词变换器应用于后置条件和异常后置条件。

谓词变换器上的偏序逐点继承自断言格：若对所有 post 和 epost 都有 x.apply post epost ⊑ y.apply post epost，则 x ⊑ y。 WP 实例产生的每个谓词变换器都是单调的：若 post ⊑ post' 且 epost ⊑ epost'，则 x.apply post epost ⊑ x.apply post' epost'。

17.2.3.1. 最弱前置条件🔗

程序类型的最弱前置条件语义由 WP 类型类提供。 实例 WP Prog Value Pred EPred 将类型为 Prog、结果类型为 Value 的程序解释为断言类型 Pred 与异常后置条件类型 EPred 上的单调谓词变换器。 类型 Prog 决定作为 outParam 的 Value、Pred 和 EPred。 函数 wp 应用该解释：wp prog post epost 是程序 prog 保证后置条件 post 与异常后置条件 epost 成立的最弱前置条件。

17.2.3.2. 保持最弱前置条件的单子🔗

vcgen 的多数内置规约引理依赖 WPMonad 实例。 WP 实例针对某个具体类型提供，但单子是多态类型。 StateM Nat Unit 与 StateM Nat String 是不同类型，但它们的最弱前置条件应当相关。 WPMonad 实例为单子可应用的每个类型所得到的类型赋予 WP 解释。 它还携带证据，说明此解释对单子的 pure 与 bind 实现是可靠的。 因此，要证明关于 Lean.Parser.Term.do : termdo 块的性质，只需证明关于该块的元素链的性质。 换言之，WPMonad 实例允许对 Lean.Parser.Term.do : termdo 块进行组合式推理。

17.2.5. 规约引理🔗

规约引理是将霍尔三元组关联到程序构造的指定定理，例如 bind、pure、循环或库函数应用。 同一程序构造可以有多个适用于不同情形的规约引理；按优先级依次尝试，直到其中一个可以实例化。

如验证条件一节所述，vcgen 通过应用程序部分与 prog 匹配的规约引理，分解目标 P ⊑ wp prog Q E。 若没有规约引理适用于 prog，vcgen 会报告错误，列出 prog 和候选引理。 规约引理使程序推理具有模块性：函数 f 的规约引理只需证明一次，vcgen 在每次调用 f 时应用它，无需展开 f 的定义。 在这方面，pure 和 bind 都是普通函数：规约引理 Spec.pure 与 Spec.bind 在具有 WPMonad 实例的任意单子中都成立。

将 spec 属性应用于陈述为霍尔三元组的定理时，会把该定理注册为规约引理。 这些引理按优先级顺序使用。

spec 属性也可以应用于定义。 用于定义时，它表示应在生成验证条件期间展开该定义。

逻辑变量是规约引理中不出现在程序里的全称量化变量。 逻辑变量用于关联初始状态、最终状态和返回值。

自动框架规约是一种规约引理：其后置条件为全称量化变量，前置条件则用该变量陈述。 vcgen 应用自动框架规约时，合一会将后置条件实例化为后续程序所需的断言，因此无需再证明该后置条件蕴含后续前置条件。 后置条件中涉及程序未改变的状态部分的所有事实，都无需额外证明即可保留。 例如，规约引理 Spec.bind 是自动框架规约：其前置条件是以第二个动作的最弱前置条件为后置条件，计算第一个动作的最弱前置条件。

函数 double 将 Nat 状态的值翻倍：

def double : StateM Nat Unit := do modify (2 * ·)

它的规约应当关联初始状态和最终状态，但无法预知它们的确切值。 该规约用逻辑变量表示初始状态：

theorem double_spec {n : Nat} : ⦃ fun s => s = n ⦄ double ⦃ fun _ s => s = 2 * n ⦄ := n:Nat⊢ ⦃ fun s => s = n ⦄ double ⦃ fun x s => s = 2 * n ⦄ n:Nat⊢ ⦃ fun s => s = n ⦄ modify fun x => 2 * x ⦃ fun x s => s = 2 * n ⦄ vcgen with All goals completed! 🐙

前置条件中的断言是函数，因为 StateM Nat 的断言类型为 Nat → Prop。

for ... in ... 循环规约所使用的循环不变式类型。 循环不变式将已消费的元素、剩余元素以及累加器状态映射为一个断言。
